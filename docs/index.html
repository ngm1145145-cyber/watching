把一台电脑的屏幕
投到你手机和另一台电脑上

Watching 是一个自己写的局域网看屏工具。被看的电脑跑一个完全静默的服务端（没有窗口，只有托盘小图标）， 手机装个 App、或者另一台电脑打开客户端、或者直接用浏览器输 IP —— 就能实时看到它的屏幕。 不经过任何服务器，不上传任何数据。

下载 Windows 版 下载安卓 APK 查看源码
🪟 Windows 10 / 11 🤖 Android 7.0+ .NET 10 零第三方依赖 MIT License 不经过任何云端

怎么连起来的

服务端抓屏 → 编码成 JPEG → 通过内置 WebSocket 推给各客户端。只有 IP 和端口，没有账号、没有中转服务器。

没人看不干活

没有查看端时抓屏线程直接退出，服务端回到 0 CPU，也不会占内存。

📉

只发最新帧

慢的客户端只会掉帧，服务端不会堆积数据，所以永远不会越看越卡。

各看各的画质

每个客户端可独立选 流畅 / 中 / 高清，互不影响，还能只传屏幕的一块区域。

两级密码

设置界面要密码（PBKDF2 哈希）＋ 客户端连接可选访问密码，双层保护。

三种查看端，按场景挑

服务端只有一个，查看端随便挑，同时连多个也没问题。

安卓 App（推荐）

真正的原生 APK，C# 写的 .NET for Android 应用，不是网页套壳。

  • 双击画面进 / 出沉浸式全屏
  • 双指捏合缩放、单指拖动平移
  • 记住地址，下次直接连
  • 退到后台自动断开省电，回来自动重连
  • 支持 adb install，不用应用商店
Android 7.0+ · 39 MB · arm64-v8a / armeabi-v7a

网页客户端

功能一览

该有的都有，不该有的（云端、账号、依赖）都没有。

🖥️

服务端完全静默

没有窗口、没有任务栏图标，只有托盘一个小图标；被截取的画面里不会出现自己。退出请右键托盘。

⚡

GDI + 系统编码器

32bpp 位图缓冲做 BitBlt，复用位图与编码参数，实测 12–20 fps（虚拟机软件渲染）。

🧩

按需裁剪

协议支持只传屏幕的一块区域，看文档时只推那一块，流量能省一大截。

🖱️

远程控制（默认关）

开启后可远程操作鼠标键盘（SendInput 注入），需要服务端本人设置密码并二次验证。

🚀

开机自启

写入当前用户启动项，无需管理员权限；开机静默待命，手机随时连。

📋

日志与诊断

界面里可直接看运行日志；附带网络诊断脚本，一键排查 IP、端口、防火墙问题。

🧱

零第三方依赖

HTTP 服务器、WebSocket（RFC6455）、抓屏编码全部自己实现，没有任何 NuGet 包。

🔐

密码怎么存

设置密码用 PBKDF2-SHA256（12 万次迭代 + 随机盐）存哈希，恒定时间比较，不保存明文。

🛡️

默认只读

装好就是「只能看」。想被操作必须被看的那台电脑自己打开开关 —— 安全默认值。

快速上手

假设 A 是被看的电脑，B 是你手上的手机或另一台电脑，两者连同一个 WiFi。

在 A 上启动服务端

解压 Watching-win-x64-selfcontained.zip，双击 shortcuts\1-启动服务端.bat，或者命令行：

Watching.exe --server
启动后 A 上看不到任何窗口，只有右下角托盘多一个蓝色眼睛图标
在 B（电脑）上打开客户端

双击 shortcuts\2-启动电脑客户端.bat 输入 A 的 IP，或者：

Watching.exe --client --connect 192.168.1.8
连上后按 F11 全屏
在 B（手机）上看

装 APK（WatchingMobile-1.0.0.apk），App 里填 A 的 IP；懒得装就用浏览器打开：

http://192.168.1.8:8899/
不知道 A 的 IP？托盘图标右键，菜单里直接列出来了
（可选）设置密码 / 开机自启

托盘图标右键 → 设置…：第一次没有密码可以直接进，进去后建议立刻设一个； 之后每次进设置都要输密码。还能在这里开启「客户端连接需要访问密码」和「开机自动启动」。

需要远程操作才打开「允许客户端远程控制」—— 默认是关的，出厂只读。

常见问题

手机连不上，一直转圈？
  • 确认手机和电脑在同一个 WiFi（不是手机流量，也不是访客网络）。
  • 电脑上运行 shortcuts\5-网络诊断.bat，它会检查监听状态、本机 IP、防火墙规则。
  • 管理员运行 shortcuts\4-添加防火墙规则.bat 放行 8899 端口。
  • 公司/学校网络可能开了客户端隔离，同网段设备互相不通，换个网络或用手机热点试试。
怎么知道服务端的 IP？

托盘图标右键，菜单里会直接列出手机可访问的地址；或者运行 shortcuts\3-查看手机访问地址.bat。 形如 192.168.x.x 或 10.x.x.x，注意别用 127.0.0.1（那是本机回环，手机连不上）。

客户端提示「服务端未开启远程控制」？

这是正常状态，默认只能看不能操作。需要操作时在服务端托盘右键 → 设置 → 打开「允许客户端远程控制」，要先设置密码并验证一次。

画面卡顿 / 流量太大？
  • 客户端点「画质」切到 流畅（1080 宽 / q45 / 12fps）。
  • 服务端设置里把「发送宽度」降到 1280 或 960。
  • 帧率 15–20 对看屏已经足够，没必要拉满。
服务端没有窗口，怎么退出？

故意的。退出方式：托盘图标右键 → 退出服务端。托盘图标被折叠的话，点任务栏的 ^ 展开隐藏图标区。

能跨公网 / 异地使用吗？

可以，但要自己打通网络：路由器上把 8899 做端口转发（强烈建议同时开启客户端访问密码）， 或者用 ZeroTier / Tailscale / WireGuard 之类把两端放进同一个虚拟局域网。Watching 本身不提供中转服务器。

忘了设置密码怎么办？

关掉服务端，编辑 %AppData%\Watching\config.json，删掉 PasswordHash 和 PasswordSalt 两行， 下次进入设置就不需要密码了。

从源码构建

需要 .NET SDK 10（Windows 端）、JDK 17 + Android SDK 36（安卓端）。

Windows 端（服务端 + 电脑客户端）

git clone __REPO__
cd watching

# 自包含版（自带运行时）
powershell -ExecutionPolicy Bypass -File .\build-release.ps1

# 轻量版（需目标机装 .NET 10 桌面运行时）
powershell -ExecutionPolicy Bypass -File .\build-release.ps1 -FrameworkDependent

安卓端（APK）

# 首次需要工作负载
dotnet workload install android

# 编译（SDK / JDK 路径可传参覆盖）
powershell -ExecutionPolicy Bypass -File .\build-apk.ps1 `
    -SdkDir "D:\android-sdk" -JdkDir "C:\jdk-17"

# 安装到手机
adb install -r dist\apk\WatchingMobile-1.0.0.apk
